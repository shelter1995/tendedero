# 0.7.3 无边框全屏游戏避让 · 2026-10-25

## 实测反馈与本机证据

用户反馈 LOL 无边框模式下偶尔自动弹出。只读取设置开关后确认当前保存的 OverFullscreen=true、HoverReveal=true、NewReveal=true，旧代码会因此直接绕过全屏避让。没有修改正在运行的旧实例或直接覆盖用户数据。

代码还存在两个独立薄弱点：只检查前台窗口，叠加层获得前台时可能漏掉后方游戏；MoveTo 在 Reveal 检查之前移动已显示窗口，存在跨屏闪出路径。旧手动展开状态也能让后续全屏检查失效。

## 处理

- 首次升级执行一次设置迁移，将旧版允许全屏自动弹出的值关闭，保留其他设置；持久化迁移版本。之后用户重新明确打开的选择会保留，不会每次启动强制关闭。
- 菜单改为“允许在全屏应用上自动弹出（含游戏）”，减少原文歧义。手动快捷键/托盘显示仍可主动打开。
- 使用系统窗口的可见状态、最小化/虚拟桌面隐藏状态、Z 顺序及 DWM 可见边框检测全屏，不访问游戏内存，不注入游戏。按屏幕判断，允许4个物理像素边缘误差。
- 小叠加层/工具窗口上方的游戏仍可被检测；较大的普通前台窗口遮住游戏时按切回桌面应用处理。忽略本应用、桌面/任务栏、点击穿透窗口与系统截图工具，避免自身窗口或 Win+Shift+S 造成误判。
- 窗口列表每200ms采样一次；显示/移动前强制刷新。短暂检测空隙保留1.5秒，按显示器独立计时；隐藏期间也更新鼠标所在屏幕的保护状态。
- 全屏保护在移动、自动展开之前执行。已有窗口立即隐藏而不是播放收起动画，并取消旧的延迟隐藏任务；不被忙碌、菜单或之前手动固定状态挡住。只对用户在已受保护状态下明确手动打开的那一轮保留例外。

## 回归与边界

先用旧行为复现边缘容差、小叠加层、短暂空隙三个失败用例，再修补。

新增12项测试覆盖边界容差、工作区最大化不误判、小叠加层、普通窗口遮挡、跨屏独立、1.5秒缓冲、迁移仅执行一次、截图工具例外、显示前刷新、负坐标、截图自动展开拦截、移动前退回隐藏状态、忙碌/固定状态下隐藏，以及用户再次明确允许全屏时的行为。用例有复合断言，总计12项。

日志：artifacts/fullscreen-build.log、artifacts/fullscreen-data/results.txt。测试使用受控窗口几何及真实隐藏 WPF 窗口，没有启动 LOL、接管键鼠或在正在进行的游戏上显示测试窗口。本机配置状态已确认，真实 LOL 无边框效果仍需用户升级后回测；不能承诺对所有游戏/叠加层绝无误判。

用户数据目录和既有标注、视频、音效、剪贴板功能保留。已有安装用户退出旧版后用0.7.3安装包升级；便携用户运行dist/Liangtu-0.7.3/Liangtu.exe。

系统依据：[GetTopWindow 的 Z 顺序](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-gettopwindow)、[GetWindow 与遍历边界](https://learn.microsoft.com/en-us/windows/desktop/api/winuser/nf-winuser-getwindow)、[GetWindowRect 与 DWM 可见边框](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect)。窗口遍历设有访问去重和数量上限。
