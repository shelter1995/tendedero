# 0.6.0 视频界面打磨与验证

日期：2026-10-24，Asia/Shanghai。

## 界面与交互

- 预览、裁剪沿用图片标注的系统标题栏、细线图标、38px 工具按钮、黑白灰表面与冷蓝强调色。文件名过长省略，完整路径保留在悬停提示中。
- 预览有独立的播放/暂停、前后定位、当前/总时长、分辨率与单条进度轨道。视频空格播放暂停，Esc 关闭；图片仍保留空格关闭与左右切换。
- 裁剪以单条胶片时间轴取代两个独立 Slider。8 张异步缩略图、双手柄、区外暗遮罩、冷蓝选区边框、独立播放指针及时间刻度共用同一轨道。
- 手柄拖动时暂停并更新预览。支持键盘左右 0.1 秒微调、Shift 加速至 1 秒；开始/结束时间支持毫秒输入。重置恢复完整范围。
- 时间输入框使用与工具栏一致的圆角、焦点色与禁用态。保存期间显示状态，禁止重复保存；失败保留原文件和选区，并恢复播放器以便重试。
- 关闭窗口取消缩略图任务，释放媒体句柄。无 FFmpeg 或取帧失败时使用已有缩略图，不阻塞播放器。

## 测试证据

1. **核心测试 46 项通过**，包括新增范围不反转/越界、极短视频、重置/定位约束、毫秒时间输入、无效数值处理。结果：`artifacts/video-polish-core.txt`。
2. **视频集成测试 14 项通过**：文件上绳、写入锁释放后收录、首帧、播放/暂停/继续/结束重播、单时间轴选区保存、取消不写入并释放文件、无障碍控件和时间字段同步、700×480 紧凑布局、失败保存恢复选区、五种格式导出及音轨保留、损坏媒体原文件保护。结果：`artifacts/video-polish-final/results.txt`。
3. **现有安全回归 74 项通过**，覆盖图片标注、剪贴板、多屏布局和手势等。结果：`artifacts/video-polish-safe/results.txt`。
4. **实际 Windows 窗口检查**：拖动起点从 2.5 秒到约 3.77 秒，画面、选区、时间字段同步；按右键增加 0.1 秒。预览与裁剪工具栏风格一致，实际胶片显示不同时间位置的帧。
5. **真实录屏副本的精确输入与保存**：在最终界面输入起点 `00:03.125`、终点 `00:08.125`，按 Enter 后时间轴同步为保留 5.00 秒。通过保存按钮导出，FFprobe 检查结果为 5.000000 秒、2468×1748、H.264/AAC。证据：`artifacts/video-design-final-ui/saved-probe.json`。原始用户录屏未用于覆盖测试。
6. **便携包校验通过**：483 个文件哈希、自带 .NET 8.0.28/WPF、原生 DLL 加载；编译 0 警告、0 错误。

## 回归中修复的问题

- 共享播放器最初在完整视频结束时由定时器提前暂停，抑制了原生 MediaEnded 事件。失败记录：`video-polish-check2/results.txt`。改为只在选区终点早于视频结尾时主动暂停，完整视频由原生事件结束并归零。
- 保存失败后重新打开媒体最初重置了选区。失败记录：`video-polish-check3/results.txt`。现在保存失败时记住起止点，媒体重开后恢复；最终回归通过。

## 交付与边界

入口：`run.cmd` 或 `dist/Liangtu-0.6.0/Liangtu.exe`。便携包：`dist/Liangtu-0.6.0-Windows-x64-portable.zip`。

本轮真实可视检查在当前深色主题和桌面 DPI 下完成，并检查了紧凑窗口渲染；明亮主题与高对比度复用 Theme 颜色与系统控件语义，未逐一切换系统设置做目测。视频时钟与帧定位受 Windows 媒体解码器影响；精确输出仍通过 FFmpeg 完成。FFmpeg 依赖和原子替换规则保持不变。
