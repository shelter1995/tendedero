# 0.4.1 多屏展开方向修补 · 2026-10-23

## 现象与根因证据

用户在两个屏幕顶边来回移动指针时，晾衣绳有时从左上、右上或正上方展开。

LineWindow.MoveTo 更新屏幕宽度后，Position 对已有卡片的 Canvas.Left/Top 无条件使用 0.55 秒重排动画。与此同时 Reveal 对整条绳子的 TranslateTransform.Y 使用展开动画。两者叠加，使屏幕有效 DIP 宽度不同的时候出现斜向移动。同宽时横坐标变化较小，看起来就接近垂直。

修复前的真实 WPF 卡片回归：目标 X=1155，实际仍为835；切到更窄屏时目标 X=643，实际仍约835；上方屏目标X=515，实际仍约835。四种切换均失败，证明旧布局动画持续影响新屏坐标。

## 修补内容

- 把屏幕局部布局从原生窗口移动中提取出来，跨屏/尺寸/DPI改变时先移除旧 Left/Top 动画，再直接设置目标位置。
- 新一轮展开前直接完成布局，只对整条绳子的 Y 做动画；当前屏已经展开时的普通列表重排仍可动画。
- 显式清理上一轮展开/收起留下的时钟，并在 Show 之前设置隐藏起点，避免旧动画覆盖新起点。展开结束回到稳定的 Y=0 基值。
- 切换屏幕时结束旧卡片的入场飞行，重置旧截图来源的偏移，避免来源坐标跨屏混用。
- 延迟收起使用代数校验，旧轮次不能隐藏新轮次的窗口；跨越屏幕顶边时重新计时悬停延迟。

## 验证

新增8项安全回归：5种显示布局切换（包括负坐标、上下排列、不同分辨率、125%/150%/200%缩放及同设备DPI变化）；旧动画清理；逐时间点检查展开只有Y变化并归零；同屏重排保留动画且跨屏定位能取消它。

原来的4项复现用例由失败转为通过。结果见 artifacts/line-motion-data/results.txt，构建日志见 artifacts/line-motion-build.log。

这些检查使用真实 WPF 元素和动画时钟，但屏幕几何是模拟输入，没有在用户的实际两台显示器上移动鼠标或展示窗口。实际双屏展开视觉仍需试用确认。之前标注与剪贴板回归继续保留。

## 运行

退出旧版后运行 run.cmd 或 dist/Liangtu-0.4.1/Liangtu.exe。在两块屏幕顶边分别停留，再反复切换，预期每次都从目标屏幕正上方垂直展开。
