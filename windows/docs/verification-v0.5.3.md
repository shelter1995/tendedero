# 0.5.3 视频流程实测

后续真实录屏发现中文 `Videos/屏幕录制` 目录未被监听，已于 0.5.4 修复并完成用户协作的实际录屏验收，见 [0.5.4 验收记录](verification-v0.5.4.md)。以下保留 0.5.3 当时的测试范围与结果。

验证日期：2026-10-23 至 2026-10-24（Asia/Shanghai）。使用本机 Windows 桌面、WPF、已安装的 FFmpeg/FFprobe。所有晾图测试实例使用工作区独立数据目录；未修改正式用户列表、截图或快捷键。

## 发现并修复

1. **预览播放到结尾后无法点击重播。** 原实现仅切换 `Play/Pause`，没有处理 `MediaEnded`，播放位置停在文件末尾。新增结束事件处理：暂停、位置归零、同步播放状态。修复前测试明确失败于 `Replay stuck at 12.00s`，修复后通过播放、暂停、继续、结尾后单击重播检查。
2. **裁剪窗口初始黑屏，暂停时拖动起点不更新画面。** 原 WPF `MediaElement` 未启用 `ScrubbingEnabled`。保持暂停预览时启用该属性，真实窗口复测已显示首帧，起点设为 2.5 秒后显示对应时间附近的帧。

生产改动仅涉及 `PreviewWindow.cs` 与 `TrimWindow.cs`；其余为版本号、入口、说明和测试。录屏监听、编码策略及图片编辑实现未改动。

| 流程 | 证据与结果 |
| --- | --- |

| 普通文件监听 | 实际 FileSystemWatcher 检测新 MP4，收录一次，缩略图为解码后的 600×338 图像。 |

| 卡片缩略图与入口 | 现有卡片测试窗口使用真实 Card，显示测试视频首帧及播放标记；中键进入预览，再从“标记 / 裁剪”进入裁剪。 |
| 预览 | 实际 WPF 媒体时钟推进、暂停后停止、再次点击继续、到结尾后单击重播均通过。 |
| 裁剪预览 | 真窗口初始首帧可见，拖动起点后暂停画面随之变化；“播放选区”到终点停止。 |
| 裁剪保存 | 从 12 秒视频选取 2.5–4.5 秒，实际触发窗口“修剪”按钮，窗口关闭并输出 2.000000 秒 MP4，含 H.264 视频和 AAC 音轨。 |
| 非关键帧裁剪准确性 | 源视频关键帧间隔为 6 秒。输出的 60 帧与原视频 2.5–4.5 秒逐帧比较，PSNR 平均 48.742147 dB，符合重新编码误差；未包含前一个关键帧处的画面。 |
| 已声明格式 | MP4、MOV、M4V、AVI、WMV 五种带音轨样本均成功截取约 2 秒，FFprobe 检查均有视频及音轨。此检查验证导出，不代表所有容器/编码组合均可由 WPF 解码。 |
| 失败保护 | 损坏视频裁剪失败，原始字节保持不变，临时文件清理。 |

## 验证边界

尝试使用 Windows 截图工具新建录屏，但自动化工具没有暴露其录制区域选择层，因此没有完成系统工具的“选择区域→开始→停止录制”全链路。已实际验证默认录屏目录的新文件自动接收，以及独立目录中模拟录制占用后完成写入的流程，不能将其表述为系统录屏按钮链路已验收。

晾衣绳透明顶层没有被电脑操作工具列为可交互窗口，因此卡片的缩略图、中键入口与裁剪入口在仓库已有 Card 测试窗口中检验；默认目录自动进入列表与自动展开通过运行实例的保存状态和日志确认。长按手势沿用现有核心测试，本轮未单独注入真实长按。

本机未验证所有第三方录屏软件、自定义/重定向录屏目录、所有视频编码，以及无 FFmpeg 环境。FFmpeg 仍不随便携包分发。
